# 오늘 · oneul — 2단계 (트레이시 필터 제외)

목표에 연결된 하루를 돌아보는 개인용 반응형 웹앱입니다. 로그인·서버·동기화·분석 도구가 없습니다. 기록은 현재 브라우저의 IndexedDB에만 저장됩니다.

## GitHub Pages에 올리기

1. 압축을 풀고 `oneul/` 폴더 **안의 내용 전체**를 `oneclickvba/oneul` 저장소 루트에 넣습니다. 폴더 자체를 다시 중첩하지 마세요.
2. 저장소의 Pages 게시 대상을 해당 브랜치 루트로 설정합니다.
3. 게시된 `/oneul/` 주소를 열고 첫 방문 때 앱 파일 다운로드가 끝나도록 잠시 기다립니다.
4. 지원하는 모바일 브라우저에서 ‘홈 화면에 추가’를 사용합니다.

앱 실행에는 빌드·패키지 설치가 필요 없습니다. `index.html`을 파일 탐색기에서 직접 열지 말고 웹 주소로 접속하세요. GitHub 저장소 업로드나 실제 Pages 배포는 이 파일 전달에 포함되지 않습니다.

## 구현 범위

- 오늘, 날짜 이동·월 이동·달력·연월 선택, 목표 띠와 이유 펼침
- 목표에 연결하는 오늘의 하나·개구리 완료, 길 찾기 행동·방해물 처리와 이월 표시
- 안 할 것 체크·연속 일수·대응 행동 보기
- 고정 순서의 여덟 갈래, 점수 재탭 해제, 기본 질문 36개, 사용자 칩 저장
- 마음에서 통제 불가 선택 시 영적 ‘맡겨 드릴 것’에 이동
- 감사·잘한 것·버릴 것, 주저리 자동 저장
- 6개 스킨·자동/밝게/어둡게, 최소 목표 관리, 안 할 것 관리, 질문 편집·추가·끄기·정렬
- 하루 경계 00/03/04시, 복귀 시 날짜 재확인, 백업 안내·JSON 교체 복원, 영구 저장 상태
- 상대 경로 PWA, 로컬 Dexie·Lucide SVG·Pretendard, 전체 정적 앱 파일 사전 캐시

상단 ‘목표’ 탭에서 목표 → 마일스톤 → 할 일을 관리합니다. 트레이시 필터는 표시하지 않습니다. 기존 필터 데이터 필드는 호환성을 위해 남겨 두되 사용하지 않습니다. 주간 리뷰는 아직 구현하지 않았습니다.

## 2단계 추가 기능

- 기존 목표 선택·새 목표 추가, 목표별 이유·마감일 확인
- 마일스톤 제목·마감일 자동 저장 및 순서 이동
- 마일스톤별 할 일 제목·우선순위·언제 어디서 할지 자동 저장
- 할 일 완료·완료 취소, 버리는 이유 필수 입력 및 복원
- 버린 일을 제외한 할 일 기준 완료 개수 표시
- 마일스톤·할 일 길게 눌러 삭제, 3초 동안 되돌리기

업데이트 전 설정에서 JSON 백업을 내보내세요. 같은 주소·같은 브라우저에서 앱 파일만 교체하면 기존 IndexedDB를 그대로 사용합니다. 브라우저의 사이트 데이터를 삭제하지 마세요. 새 앱이 보이지 않으면 앱과 해당 사이트의 모든 탭을 닫고 다시 열어 주세요. 오프라인 캐시 갱신을 위해 첫 실행은 인터넷에 연결해 주세요.

## 조작

- 영역 이름을 누르면 질문 창이 열립니다. 창 위쪽 화살표 또는 헤더 위아래 스와이프로 영역을 옮깁니다. 질문 본문의 세로 스크롤과 충돌하지 않도록 영역 전환 스와이프는 헤더에서 받습니다.
- 점수는 즉시 저장되며 같은 점수를 다시 누르면 해제됩니다.
- 해야 할 것을 길게 누르면 오늘의 하나로 올립니다. 탭하면 완료 상태를 바꿉니다.
- 안 할 것 제목을 누르거나 길게 누르면 ‘이 상황이 오면 이렇게’ 내용을 봅니다.
- 감사·잘한 것·버릴 것 항목 삭제는 길게 누릅니다. 3초 동안 되돌릴 수 있습니다. 설정의 삭제 버튼도 길게 누릅니다.
- 새 목표는 일시 정지 초안입니다. 제목 등을 적고 상태를 진행 중으로 바꾸면 오늘에 표시됩니다. 진행 중 목표는 3개까지입니다.
- 오늘의 하나·해야 할 것의 미연결 입력도 초안으로 기기에 남지만, 목표를 연결하기 전에는 완료 체크나 길 찾기 행동 표시가 활성화되지 않습니다.
- 미래 날짜에는 오늘의 하나와 해야 할 것만 입력할 수 있습니다.

## 보관과 복원

설정에서 JSON을 내보내 별도 보관하세요. 브라우저 데이터 삭제·사생활 모드 종료·기기 분실을 앱이 막을 수는 없습니다. 영구 저장 요청은 브라우저가 거부할 수 있으며 설정에 상태가 표시됩니다. 다운로드 시작을 백업 시점으로 기록하므로 실제 파일 다운로드 완료도 확인하세요.

가져오기는 모든 12개 테이블이 포함된 `format: oneul`, `version: 2` 백업을 검사한 뒤 덮어쓰기 확인을 받고 단일 트랜잭션으로 교체합니다. 손상·중복 키·잘못된 점수·없는 목표 참조 등을 거부합니다. 덮어쓰기 전에 현재 기록을 내보내세요.

버전 1→2 마이그레이션은 동일 이름 `oneul` DB와 문서화한 이전 테이블 구조를 기준으로 합니다. 관계-회사/관계-가족은 날짜별로 합쳐 높은 점수를 남기고 메모를 합칩니다. 충돌한 원문은 `migrationSources`에 보존합니다. 몸상태는 archived로 보관하고 공부는 공부·기술로 바꿉니다. 실제 기존 앱의 DB 이름이나 테이블 구조가 다르면 그 원본에 맞춘 별도 조정이 필요합니다.

## 파일 구성

`index.html`, `app.js`, `style.css`가 진입 화면이며 `db.js`, `settings.js`, `icons.js`는 분리된 ES 모듈입니다. `vendor/`에는 실행 시 네트워크 의존성이 없는 라이브러리·폰트·라이선스가 있습니다. `sw.js`, `manifest.json`, `icons/`는 PWA 파일입니다.

캐시는 설치 시 전체 목록을 원자적으로 받습니다. 새 버전은 열려 있는 기존 탭이 모두 닫힌 뒤 활성화됩니다. 코드 변경 시 배포 묶음의 유지보수용 `prepare_release.py`로 캐시 해시와 파일 목록을 재생성하거나 `sw.js`의 캐시 버전·목록을 직접 갱신하세요. 앱 사용자가 실행할 빌드 단계는 아닙니다.

## 검증과 한계

검증 결과는 배포 묶음의 `TEST-RESULTS.md`를 참고하세요. DOM 기반 기능 시험·가짜 IndexedDB 시험·서비스워커 캐시 핸들러 시험은 실제 모바일 브라우저 시험을 대체하지 않습니다. 홈 화면 설치, 실제 비행기 모드 재실행, 운영체제가 앱을 강제 종료하는 순간의 저장, iOS/Android의 영구 저장 허용 여부는 대상 기기에서 마지막 확인이 필요합니다.

디자인은 요청한 색상을 사용합니다. 3점 버튼 흰 글자는 요청한 예외를 따릅니다. 다른 점수의 파스텔 배경에는 다크 모드에서도 어두운 글자를 사용합니다. 일반 보조 문구는 가독성을 위해 --sub보다 진한 파생 색상으로 표시합니다.
